# Mod-like content with vanilla clients: textures, 3D models, GUIs, mobs, vehicles

Players use an unmodified client. Everything visual comes from a **resource pack that the server builds and
pushes live**: put standard resource-pack files in `modules/<id>/assets/<namespace>/...`; about 1 s after you
save (or after a reload / disable), the server merges the `assets/` of every running module, validates them,
and sends the new pack to every player. The client reloads its resources in place (a short loading screen,
**no disconnect**). Players who decline the pack see the vanilla base items instead (keep the game playable).

## 1. Layout and rules

```
modules/<id>/
  MyModule.java
  assets/<ns>/                       <ns> = your own namespace: short, lowercase, e.g. your module id without '-'
    textures/item/gem.png.txt        pixel art source -> textures/item/gem.png (section 3)
    textures/item/ruby.png           real PNG (e.g. generated by POST /textures, section 2)
    textures/block/ore.png.b64       base64 PNG -> textures/block/ore.png
    models/item/gem.json             3D model (cuboids, section 4)
    shapes/car.shape.json            realistic 3D object from primitives -> item ns:car (section 9)
    shapes/lamp.obj + lamp.mtl       realistic 3D object from an OBJ mesh -> item ns:lamp (section 9)
    items/gem.json                   item model definition: {"model":{"type":"minecraft:model","model":"<ns>:item/gem"}}
    font/menu.json                   custom font (GUI backgrounds, icons in text, section 6)
    sounds.json + sounds/*.ogg       custom sounds (real .ogg files only)
```

- Paths: lowercase `a-z 0-9 _ . - /` only (no uppercase, no spaces). Resource ids: `<ns>:item/gem` = `assets/<ns>/textures/item/gem.png`
  (textures) or `assets/<ns>/models/item/gem.json` (models). The `minecraft` namespace overrides vanilla files (avoid it).
- Two modules providing the same file: the first (alphabetical) wins, both get a warning. Use your own namespace.
- Check after every change: `curl -s http://127.0.0.1:8765/api/pack` -> `issues` (module, file, level, message), or
  `modules/<id>/.vibe/assets.log`; problems also appear in `GET /api/modules/<id>/logs`. An ERROR file is left out
  of the pack (the rest still works). Asset changes do not need a module reload; Java changes still do.
- Base item for custom items: any item (STICK, PAPER...) + `meta.setItemModel(new NamespacedKey("<ns>", "gem"))`
  (= `assets/<ns>/items/gem.json`). Equivalent: `item.setData(DataComponentTypes.ITEM_MODEL, Key.key("<ns>", "gem"))`.

## 2. Textures: generate them (preferred)

The server calls an image model (OpenRouter, key kept server side), converts the picture to a Minecraft-looking
PNG (background removed, cropped, downscaled, palette reduced, optionally seamless) and writes it into your module:

```bash
curl -s -X POST http://127.0.0.1:8765/api/modules/<id>/textures -d '{"path":"assets/<ns>/textures/item/ruby.png","prompt":"a shiny red ruby gem"}'
```
Answer: `{"ok":true,"path":...,"width":16,"height":16,"colors":14,"model":...,"cost":0.04,...}` (takes 5-30 s).
Then reference it as `<ns>:item/ruby` in a model. The pack is rebuilt and pushed automatically.

| field | default | |
|---|---|---|
| `path` | required | `assets/<ns>/textures/<folder>/<name>.png` inside your module |
| `prompt` | required | what to draw, **English, ASCII** (curl mangles accents) |
| `kind` | from the folder | `item` (transparent, cropped, 16), `block` (seamless tile, 16), `entity`/`skin` (64, full frame), `gui` (128), `realistic` (photo-like seamless material, 128, all colours: for section 9 objects), `decal` (photo-like picture, 128, all colours), `other` |
| `size` / `width`,`height` | by kind | 4..512 |
| `transparent`, `seamless`, `crop` | by kind | booleans |
| `colors` | 16 / 24 / 48 | palette size (0 = keep all colours) |
| `style`, `model` | | override the style sentence / the OpenRouter image model |

Errors: 503 = no OpenRouter key on the server (then use pixel art, section 3), 429 = too many requests (wait),
400 = bad field (message says which). One curl per texture; generate only what you need (it costs money).
Good prompts: one object, simple shapes, strong colours ("a green slime ball with a white highlight").
For a 3D model, generate small material textures (`kind:"block"`, e.g. "rusty metal plates") and map them on cuboids.

## 3. Textures as text: pixel art (`*.png.txt` or `*.texture.json`)

```json
{
  "palette": {".": "transparent", "k": "#1b1b1b", "r": "#d42a2a", "R": "#ff7070", "w": "#ffffff"},
  "pixels": [
    "................",
    "......kkkk......",
    ".....krrRRk.....",
    "....krrrrRwk....",
    "....krrrrrRk....",
    "....krrrrrrk....",
    ".....krrrrk.....",
    "......kkkk......",
    "................"
  ]
}
```
- One character per pixel (any single character), all rows the same length. Colours: `#rgb`, `#rrggbb`,
  `#rrggbbaa`, `transparent`. Item textures: 16x16 (rows above shortened for the example).
- `"scale": 2` = each character becomes 2x2 pixels.
- Animation: `"frames": [[rows...], [rows...]]` + `"frametime": 4` (ticks per frame) -> vertical strip + `.png.mcmeta`.
- Big textures (GUIs, atlases) are drawn with shapes instead of rows: `"size": [176, 166]`, `"fill": "#241733"` or a
  palette char, and `"draw"`: a list of `{"rect": [x, y, w, h], "color": c}` (filled), `{"frame": [x, y, w, h], "color": c,
  "thickness": 1}` (outline), `{"line": [x1, y1, x2, y2], "color": c}`, `{"pixels": [rows], "at": [x, y]}` (stamp,
  transparent chars keep what is below); any op takes `"repeat": [nx, ny], "step": [dx, dy]` (grids of slots).
  Example: `examples/custom-gui/assets/vgui/textures/gui/menu.png.txt`.
- `*.png.b64`: a real PNG as base64 text (a `data:image/png;base64,` prefix is allowed).

## 4. 3D models (Blockbench JSON, plain text)

A model is a list of cuboids in a 16x16x16 pixel box (1 block). Worked example: `examples/laser-gun`.

```json
{
  "textures": {"0": "laser:item/laser_gun", "particle": "laser:item/laser_gun"},
  "elements": [
    {"from": [2, 6, 6], "to": [12, 10, 10], "faces": {"north": {"uv": [0, 0, 8, 4], "texture": "#0"}, "east": {...}, "south": {...}, "west": {...}, "up": {...}, "down": {...}}},
    {"from": [3, 1, 7], "to": [6, 6, 9], "rotation": {"angle": -22.5, "axis": "z", "origin": [4.5, 6, 8]}, "faces": {...}},
    {"from": [14, 6.5, 6.5], "to": [15, 9.5, 9.5], "light_emission": 15, "faces": {...}}
  ],
  "display": {
    "thirdperson_righthand": {"rotation": [0, -90, 0], "translation": [0, 3, 1], "scale": [0.6, 0.6, 0.6]},
    "firstperson_righthand": {"rotation": [0, -90, 5], "translation": [1.5, 2.5, 0], "scale": [0.6, 0.6, 0.6]},
    "gui": {"rotation": [15, -30, 0], "scale": [0.9, 0.9, 0.9]},
    "ground": {"translation": [0, 2, 0], "scale": [0.5, 0.5, 0.5]},
    "fixed": {"scale": [1, 1, 1]}
  }
}
```
- `from`/`to`: corners in pixels, **each coordinate within -16..32** (else the client rejects the whole model).
  x = east, y = up, z = south. Decimals are fine.
- `faces`: `north south east west up down`; `uv` = `[u1, v1, u2, v2]` in 0..16 of the texture (pick a region of
  one colour/pattern); omit a face to make it invisible. `"texture": "#0"` refers to the `textures` map.
- One small texture "atlas" (16x16 with colour blocks: metal, glow, dark...) for the whole model is the easiest.
- `rotation` (26.3 clients): `{"origin": [8, 8, 8], "axis": "z", "angle": 30}` with ANY angle, or Euler angles
  `{"origin": [8, 8, 8], "x": 10, "y": 45, "z": -20}` (degrees, applied X then Y then Z). `origin` = pivot in pixels.
  Only `from`/`to` must stay within -16..32 (rotated corners may go beyond). Every element needs at least one face.
- `light_emission`: 0..15, makes an element glow in the dark.
- `display`: how the item sits in hands/GUI/ground/item frames/display entities (`fixed`). Without it the model is
  drawn as is (1 block centred). Optional `"parent": "minecraft:item/handheld"` reuses vanilla transforms.
- Flat 2D item (no modelling): `{"parent": "minecraft:item/generated", "textures": {"layer0": "<ns>:item/gem"}}`.
- Item definition `assets/<ns>/items/gem.json`: `{"model": {"type": "minecraft:model", "model": "<ns>:item/gem"}}`.
  The server checks that referenced models/textures exist (missing texture = purple/black checkerboard).

## 5. New-looking mobs and animated props (display entities)

Pattern of `examples/robot-mob` (copy it):
- A vanilla mob gives hitbox, health, pathfinding and attacks: `Husk` (no sun burn) with `setInvisible(true)`,
  `setSilent(true)`, `setPersistent(false)`; keep its custom name visible as a name tag.
- Its look = `ItemDisplay` entities with custom item models, added as passengers (`base.addPassenger(part)`):
  they follow it for free. Every tick or two, `part.setRotation(base.getBodyYaw(), 0)` so they face where it walks.
- Place/scale parts with `setTransformation(new Transformation(translation, leftRotation, scale, rightRotation))`
  (JOML `Vector3f`, `Quaternionf`); passengers sit on top of the mob, so use a negative y translation.
  `ItemDisplayTransform.FIXED`, `setBrightness(new Display.Brightness(15, 15))` to stay visible at night.
- Animation = set a new transformation with `setInterpolationDelay(0)` + `setInterpolationDuration(n)`: the client
  smooths over n ticks (bobbing, spinning: rotate <= 90 degrees per step, scale pulses...).
- Custom AI in `ctx.every(...)`: `mob.setTarget(player)`, ranged attacks with particles + `player.damage(x, mob)`.
- `ctx.entity(...)` on the base AND every part (removed on reload); cap the count; on `EntityDeathEvent` remove parts.
- Static props / furniture / holograms: just an `ItemDisplay` (or `BlockDisplay`/`TextDisplay`) + `ctx.entity`.
  Clickable props: add an `Interaction` entity (`setInteractionWidth/Height`) and listen to `PlayerInteractEntityEvent`.

## 6. Textured GUIs (chest menus with a custom background)

Trick used by `examples/custom-gui`: the whole background is **one glyph of a custom font**, put in the inventory title.
```json
{"providers": [
  {"type": "space", "advances": {"": -8, "": -169}},
  {"type": "bitmap", "file": "vgui:gui/menu.png", "ascent": 13, "height": 166, "chars": [""]}
]}
```
- Title (Java): `Component.text("").font(Key.key("vgui", "menu")).color(NamedTextColor.WHITE)`
  then `.append(Component.text("My title", NamedTextColor.GOLD))` as a sibling (not a child of the font component).
  `` moves the pen 8 px left (title starts at x=8), `` draws the 176 px wide background, `` moves
  back 169 px (= 176 + 1 - 8) so the title text starts where it normally does. White = no tint.
- Chest sizes (background textures): 27 slots = 176x166 (`ascent` 13, `height` 166), 54 slots = 176x222.
  Slots: top-left slot frame at (7, 17), 18 px apart; player inventory at (7, 83) (3 rows), hotbar at (7, 141)
  for the 27-slot chest. Keep `ascent <= height`. Use private-use characters `-`, unique per font.
- Clicks: `InventoryHolder` class + `InventoryClickEvent` (cancel, then act on `e.getSlot()`), see CLAUDE.md section 7.
- Same trick for HUD icons in the action bar / boss bar / chat: a bitmap glyph (`height` ~9, `ascent` ~8).

## 7. Rideable vehicles

`examples/hover-car`: the vehicle is an `Interaction` entity (invisible, no physics, clickable) with the model
(`ItemDisplay`) and the player as passengers. Each tick read `player.getCurrentInput()` (`isForward()`,
`isBackward()`, `isLeft()`, `isRight()`, `isJump()`, `isSprint()`; `isSneak()` = vanilla dismount) and move the
vehicle with `vehicle.teleport(to, TeleportFlag.EntityState.RETAIN_PASSENGERS)` along `player.getLocation().getDirection()`.
`PlayerInputEvent` fires when keys change. Stop at solid blocks; remove abandoned vehicles.

## 8. Common mistakes

| Symptom / issue | Fix |
|---|---|
| purple/black checkerboard | texture path wrong (`<ns>:item/x` -> `assets/<ns>/textures/item/x.png`) or the texture had an ERROR |
| item shows as the base item | `items/<name>.json` missing/invalid, `setItemModel` key differs, or player declined the pack |
| whole model invisible | a coordinate outside -16..32, an element without faces, or JSON error (see `issues`) |
| 3D object looks hollow / inside out | OBJ faces must be counter-clockwise seen from outside; look at `.vibe/previews/` |
| GUI background shifted | wrong `ascent`/`height`/space advances, or the title font set on the parent component |
| "non-standard JSON" warning | no comments, no trailing commas, double quotes only |
| nothing changes in game | `GET /api/pack`: is your module listed in `modules`? (only ENABLED modules contribute) |

## 9. Realistic 3D objects (car, guitar, lamp, statue, furniture, spaceship...): `*.shape.json` / `*.obj`

Describe the object as TEXT; the server compiles it into vanilla models made of cuboids at any angle (26.3 clients
accept any element rotation), with colours, baked light and textures in a generated atlas. Not limited to the
Minecraft look: curves are true facets (a 28-sided wheel, a smooth vase), not stairs. No paid 3D service needed.

```
modules/<id>/assets/<ns>/shapes/<name>.shape.json   ->  object <ns>:<name>     (or <name>.obj + <name>.mtl)
```
- Result: item `<ns>:<name>` (whole object fitted in 1 block: held, item frame, GUI), one model per part for big world
  objects (`Models.spawn`), and a **preview `modules/<id>/.vibe/previews/<ns>_<name>.png` (4 views): Read it** to check
  the shape, fix the source, save again. `GET /api/pack` -> `models` (elements, size, parts), `issues` (errors with the
  JSON path, e.g. `parts.body.shapes[3].radius must be > 0`). Also in `.vibe/assets.log`.
- Units: **blocks (1 = 1 m), y up, front = +z, y = 0 = ground** (the object stands on the spawn location, facing its yaw).

Worked example (`examples/sports-car/assets/sportscar/shapes/roadster.shape.json`, shortened):
```json
{
  "detail": "high",
  "materials": {"paint": "#c8102e", "tire": "#1c1c1e", "rim": "#a7adb7", "glass": {"color": "#a9d4ff70", "double_sided": true},
                "headlight": {"color": "#fff7d6", "glow": 13}, "leather": {"texture": "sportscar:block/leather", "tile": 0.5}},
  "parts": {
    "body": {"shapes": [
      {"type": "extrude", "material": "paint", "rotate": [0, -90, 0], "depth": 1.86,
       "points": [[-2.22, 0.30], [2.12, 0.30], [2.27, 0.52], [1.60, 0.76], [0.30, 0.86], [-2.00, 0.90], [-2.28, 0.60]]},
      {"type": "polygon", "material": "glass", "points": [[-0.8, 0.86, 0.52], [0.8, 0.86, 0.52], [0.74, 1.22, 0.24], [-0.74, 1.22, 0.24]]},
      {"type": "box", "material": "leather", "size": [0.5, 0.48, 0.12], "at": [0.36, 1.08, -0.68], "rotate": [-12, 0, 0], "round": 0.05, "mirror": "x"},
      {"type": "box", "material": "headlight", "size": [0.42, 0.09, 0.30], "at": [0.62, 0.68, 2.02], "rotate": [-16, 0, 0], "mirror": "x"}
    ]},
    "wheel_fl": {"pivot": [0.80, 0.36, 1.35], "shapes": [
      {"type": "cylinder", "material": "tire", "axis": "x", "radius": 0.36, "height": 0.27, "at": [0.80, 0.36, 1.35], "segments": 28},
      {"type": "cylinder", "material": "rim", "axis": "x", "radius": 0.24, "height": 0.29, "at": [0.80, 0.36, 1.35]}
    ]}
  }
}
```
(The body is the car's side silhouette, with wheel arches, extruded across its width: the best trick for vehicles.)

| shape `type` | fields (plus common: `at` centre, `rotate` [x,y,z] degrees, `material`, `mirror`, `segments`, `glow`, `double_sided`) |
|---|---|
| `box` | `size` [w,h,d] (+ `at`) or `from`/`to`; `faces` {"up": "glass", "down": "none"}; `round`: edge radius |
| `cylinder` | `radius`, `height`, `axis` x/y/z; `radius_top`/`radius_bottom` (tapered); `caps` both/top/bottom/none; `cap_material` |
| `cone` | `radius`, `height` (apex up, along `axis`) |
| `sphere` | `radius` or `radii` [x,y,z] (ellipsoid); `rings`; `from_angle`/`to_angle` (0 = bottom pole .. 180 = top; 90..180 = dome) |
| `capsule` / `torus` | `radius`, `height` (total), `axis` / `radius` (ring), `tube`, `axis` |
| `lathe` | `profile` [[r, y], ...] bottom to top, revolved around `axis`: vases, bottles, lamp shades, columns, rims |
| `extrude` | `points` [[x, y], ...] any outline (no holes), extruded along local z over `depth`; `side_material` |
| `polygon` | `points` [[x, y, z], ...] planar polygon (windshields, panels), counter-clockwise seen from the visible side |
| `mesh` | `obj`: "file.obj" (relative to this file), `scale` |

- `mirror`: `"x"` adds a copy mirrored across x = 0 (`["x", "z"]` = 4 copies): write symmetric objects once.
- Top level: `materials`, `shapes` (one part) or `parts` {name: {`pivot`, `shapes`}} (one part per moving piece:
  wheels, doors, rotors; `pivot` = rotation centre), `detail` low/medium/high/ultra (12/20/32/48 segments for round
  shapes), `size` (rescale: largest dimension in blocks), `light` 0..1 (baked shading, default 0.6), `mode`
  exact/voxel/auto, `resolution` (voxel mode), `origin` keep/bottom/center, `max_elements` (4000), `display`.
- Materials: `"#rrggbb"` or `"#rrggbbaa"` (alpha = translucent, e.g. glass), or {`color` (tints the texture),
  `texture` "ns:block/x" (a PNG of your module), `tile` (blocks per repeat, default 1), `mapping` "box" (projected,
  tiles) or "face" (whole picture on each face: screens, paintings, labels), `glow` 0..15, `double_sided`, `shade`}.
- Realistic textures: `curl -s -X POST .../api/modules/<id>/textures -d '{"path":"assets/<ns>/textures/block/leather.png","prompt":"brown leather","kind":"realistic"}'`
  (128x128 photo-like, seamless, all colours), then `{"texture": "<ns>:block/leather"}`. `"kind":"decal"` = a picture
  (logo, painting) for `"mapping": "face"`. Vanilla textures (`minecraft:...`) cannot be used here.
- OBJ (`examples/floor-lamp/assets/lamp/shapes/floor_lamp.obj`): `v x y z`, `f 1 2 3 4` (also `v/vt/vn`), `o`/`g`,
  `usemtl`, `mtllib x.mtl` (`newmtl`, `Kd r g b` 0..1, `d` alpha, `Ke` glow, `map_Kd` texture). Faces
  counter-clockwise seen from outside (an inside-out mesh is flipped, with a warning). Options in a comment line:
  `# vibecraft {"size": 1.6, "detail": "high"}`. Origin: bottom centre. Dense meshes switch to voxel mode (stairs).
- Budget: 200-1500 elements per object is fine (car ~850, lamp ~750); part models are split every 1024 elements.
  Round shapes cost the most: give small round parts fewer `segments`.

Place it in the world (Java, main thread):
```java
import dev.vibecraft.api.Models;            // + org.joml.Quaternionf
if (!Models.exists("sportscar:roadster")) { sender.sendRichMessage("<yellow>Modèle en préparation..."); return; }
Models.Model car = Models.spawn(ctx, "sportscar:roadster", loc, 1.0);  // one ItemDisplay per part, removed on reload
car.teleport(loc2);                                                    // moves + turns to loc2's yaw (smooth)
car.rotatePart("wheel_fl", new Quaternionf().rotateY(steer).rotateX(spin), 1);  // around the part's pivot
car.ride(seat);       // displays become passengers of an Interaction seat (vehicles: examples/sports-car)
p.give(Models.item("lamp:floor_lamp"));                                // the whole object as an item
```
Also `Models.size(id)`, `Models.parts(id)`, `model.setYaw(f)`, `model.displays()`, `model.remove()`. Re-spawn after
changing a shape's parts or size.
